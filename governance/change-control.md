# Change control and review record

The feature specification is reviewed before implementation and names every
requirement id, acceptance criteria, and verification method. The implementation plan identifies review owners and required test evidence. The implementation plan is versioned with the change. Change control records
review evidence, approval, and the linked pull request.

Emergency change records include risk acceptance and a post-incident review.
Repository history and plan retention preserve an audit trail for the approved
retention period. Completed work is committed in coherent revisions before
handoff so each change has a revertible revision; the completion report
identifies the commit and confirms that task-owned changes are clean.
