# torviello-engine

Core PyTorch inference runtime. Brand message: Inference built for AI-native systems.

## Layout

- `domain/` — domain model, invariants, lifecycles, events, and ownership.
- `specifications/` — use cases, requirement IDs, and acceptance criteria.
- `contracts/` — machine-readable interfaces and event schemas.
- `src/` — reserved production location; the current scaffold lives in `services/engine`.
- `tests/` — reserved for engine tests; the current scaffold tests live in `services/engine/tests`.
- `evaluations/` — plans, datasets, reports, and release decisions.

## Scope

The engine serves local inference across speech synthesis, speech transcription, image classification, object detection, generic tensors, and an optional assistant proxy. It owns model identity, the model lifecycle, backend selection, admission and limits, result attribution, and redaction. It does not require an account, control plane, or outbound network after required assets are prepared.

## Packaging

Per [GOV-12](../torviello-enforcer/governance/rules/12-independent-unit-packaging.md), this unit is packageable as an independent, versioned artifact (engine library and CLI distributions); its packaging manifest, version, and build command live inside this unit, never at the repository root. Status: the engine profile builds and validates on macOS with driver unit tests, the Windows MSI installer is generated by the CI `windows-installer` job from the deterministic WiX definition, and the full profile declares its libtorch cache contract — Linux bundle and smoke evidence on clean hosts is recorded through CI, not yet on a dedicated Linux host.

## Validation

Run the repository checks from the root:

```sh
uv sync --locked
uv run pytest
cargo test --workspace --locked
npm ci && npm run build && npm test
```

Scaffold tests are not evaluation evidence. The recorded CPU classifier report is local performance evidence only; record broader evaluation evidence in `evaluations/` after the required models, datasets, and workloads exist. Follow `GOV-06` through `GOV-10` in `../torviello-enforcer/governance/`.

## Status

Domain model, full capability requirements, features, acceptance checks, the HTTP contract, and the HPA-4 assurance standard are drafted.

A non-production scaffold exists under [`services/engine`](services/engine) and [`../torviello-landing/web/src/console`](../torviello-landing/web/src/console). It has a buildable Rust API shell, HS256 authentication, configuration validation, RFC 9457 errors, and unit/contract/integration tests, plus a React console shell. It **does** implement a validated model catalog, confined local acquisition with digest verification, acquisition job status and SSE progress, and a load lifecycle with single-flight initialization, reference-aware unload, and a capacity policy. The bundled `engine-demo-tensor` asset uses a reference CPU linear-classifier adapter (`torviello-tensor-v1`), and `engine-demo-torchscript` executes a traced image classifier through TorchScript on CPU when built with the `torchscript` feature. `POST /classify` returns ordered top-k results for that fixture. It does **not** implement remote Hugging Face acquisition, managed-asset deletion, the remaining inference routes, persistence, OpenTelemetry export, WebSocket transport, or the full 22-path canonical contract (23 canonical operations, 32 with aliases). It has no formal model, fuzz corpus, provenance attestation, or full product evaluation. A local CPU performance report for the TorchScript classification fixture exists at [`../torviello-bench/evaluations/reports/2026-10-22-classify-cpu`](../torviello-bench/evaluations/reports/2026-10-22-classify-cpu); it is not product conformance.
