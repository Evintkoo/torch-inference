### OPS-03 — Installation, service managers, and deployment profiles

*Domain:* [operations](../../../torviello-enforcer/operations/README.md) · *Rule:* [03-installation-service-managers-and-deployment-profiles.md](../../../torviello-enforcer/operations/rules/03-installation-service-managers-and-deployment-profiles.md)

**Control objective.** This control defines the intended outcome for **installation, service managers, and deployment profiles** and the evidence needed to assess it across normal operation, boundary conditions, failures, and change.

#### OPS-03.01 — Every supported deployment profile MUST state target OS/architecture…

**Requirement:** Every supported deployment profile MUST state target OS/architecture, prerequisites, filesystem paths, service identity, required ports, data directories, model storage, configuration source, and network dependencies.

#### OPS-03.02 — Install and upgrade procedures MUST be repeatable from…

**Requirement:** Install and upgrade procedures MUST be repeatable from a clean machine and MUST distinguish administrator actions from service-user actions. The service MUST run with least privilege and writable paths limited to documented state/cache locations.

#### OPS-03.03 — Service definitions MUST set restart policy, startup ordering…

**Requirement:** Service definitions MUST set restart policy, startup ordering, graceful stop timeout, environment/config source, resource limits, and log routing appropriate to the target service manager.

#### OPS-03.04 — Container images MUST pin base image identity, use…

**Requirement:** Container images MUST pin base image identity, use non-root execution where feasible, include only runtime artifacts, define health checks, and avoid embedding secrets or mutable model downloads in image layers.

#### OPS-03.05 — Network listeners MUST bind to the intended interface by…

**Requirement:** Network listeners MUST bind to the intended interface by default. Remote exposure MUST require an explicit deployment choice and documented authentication, TLS termination, firewall, and proxy trust policy.

#### OPS-03.06 — First startup MUST distinguish missing prerequisites from corrupt state…

**Requirement:** First startup MUST distinguish missing prerequisites from corrupt state and transient dependency failures; automated restart MUST use backoff and MUST not create a restart loop that hides permanent configuration errors.

#### OPS-03.07 — Installation MUST preserve user data and configuration on upgrade…

**Requirement:** Installation MUST preserve user data and configuration on upgrade; uninstall MUST explain which state is retained or removed and require explicit confirmation before destructive deletion.

#### PORT-03.01 — Every supported target MUST specify OS edition/version, architecture/ABI…

**Requirement:** Every supported target MUST specify OS edition/version, architecture/ABI, CPU baseline and required instruction sets, compiler/toolchain, libc/runtime, service manager, graphics/accelerator prerequisites, and support level.

#### PORT-03.02 — Support status MUST distinguish compile-only, build-and-test, release-qualified…

**Requirement:** Support status MUST distinguish compile-only, build-and-test, release-qualified, and best-effort targets. Borrow Rust target tiers as evidence about toolchain support only; they do not prove application support.

#### PORT-03.03 — Each advertised target MUST have an owner, CI…

**Requirement:** Each advertised target MUST have an owner, CI or release-qualification evidence, known limitations, minimum resources, install/uninstall process, and end-of-life policy.

**Requirement:** Filesystem code MUST handle platform path separators, case sensitivity, Unicode normalization, reserved names, maximum path lengths, permissions, atomic rename limits, and removable/network-mounted filesystems where supported.

**Requirement:** Process execution MUST use argument arrays and explicit working directory/environment. Shell interpretation MUST NOT be used for untrusted values; child process handles, exit codes, signals, timeouts, and cleanup MUST be managed on every target.

**Requirement:** Network behavior MUST state proxy support, DNS resolution, TLS trust-store source, IPv4/IPv6 behavior, timeout, retry, and offline mode. Optional service discovery MUST degrade safely when outbound access is disabled.

#### PORT-04.05 — Package installation MUST account for Windows ACLs, Unix…

**Requirement:** Package installation MUST account for Windows ACLs, Unix ownership/modes, macOS signing/notarization, antivirus quarantine, and platform-specific application data directories as applicable.

#### PORT-04.06 — Line endings, locale, timezone, decimal formats…

**Requirement:** Line endings, locale, timezone, decimal formats, and environment variable case sensitivity MUST not alter serialized configuration or protocol behavior.

#### PORT-04.07 — Cross-platform tests MUST cover path creation and cleanup…

**Requirement:** Cross-platform tests MUST cover path creation and cleanup, atomic update, Unicode names, process cancellation, permissions, and offline startup on each claimed OS family.

### REL-01 — Reproducible cross-platform packaging

*Domain:* [releases](../../../torviello-enforcer/releases/README.md) · *Rule:* [01-reproducible-cross-platform-packaging.md](../../../torviello-enforcer/releases/rules/01-reproducible-cross-platform-packaging.md)

**Control objective.** These controls govern **reproducible cross-platform packaging**. The intended outcome is that every applicable requirement is implemented at the correct system boundary, produces the specified behavior under normal and adverse conditions, and can be verified from current repository or runtime evidence.

#### REL-01.01 — Keep release/package definitions under /packaging and container definitions under

The project MUST keep release/package definitions under /packaging and container definitions under /containers. The project MUST also provide an automation entry point that works across supported Windows, macOS, and Linux build environments.

#### REL-01.02 — Make platform-specific shell scripts the sole build or install

The project MUST NOT make platform-specific shell scripts the sole build or install path. The project MUST also use a declarative or cross-platform workflow and keep shell scripts as optional wrappers only.

#### REL-01.03 — Record source revision, toolchain, dependency lock state, feature flags

The project MUST record source revision, toolchain, dependency lock state, feature flags, model/runtime artifacts, environment inputs, and package commands for every artifact.

#### REL-01.04 — Support offline artifact construction from checked-in source

The project MUST support offline artifact construction from checked-in source and a documented prepared cache. Distinguish online preparation of dependencies from the offline build itself.

#### REL-01.05 — Pin release inputs and produce the same artifact from

The project MUST pin release inputs and produce the same artifact from equivalent inputs where the platform permits. The project MUST also document nondeterministic platform signing/notarization steps separately.

#### REL-01.06 — Build and install-test each product profile on its supported

The project MUST build and install-test each product profile on its supported operating systems. The project MUST also exercise first start, health, graceful stop, upgrade, and rollback.

### REL-05 — Install, upgrade, migration, and rollback

#### REL-05.01 — Installers MUST verify package identity and integrity before executing…

**Requirement:** Installers MUST verify package identity and integrity before executing privileged operations and MUST explain requested privileges and network access.

#### REL-05.02 — Upgrade MUST stage new binaries and configuration, validate…

**Requirement:** Upgrade MUST stage new binaries and configuration, validate prerequisites and migrations, switch active versions atomically where feasible, and retain the previous known-good state until health verification passes.

#### REL-05.03 — Configuration and database migrations MUST be versioned, backed…

**Requirement:** Configuration and database migrations MUST be versioned, backed up when destructive, observable, and compatible with the rollback policy. If downgrade is unsupported, the installer MUST block it before modifying state and explain forward recovery.

**Requirement:** Model assets MUST be versioned independently from binaries when their size or lifecycle warrants it; model rollback MUST verify compatibility with the target runtime version.

**Requirement:** Rollback MUST verify artifact integrity, restore compatible configuration/registry, and confirm readiness before returning traffic. Rollback MUST not reuse compromised signing keys or vulnerable artifacts without explicit risk approval.

### SEC-13 — Physical Workspace Remote Work and Asset Protection

*Domain:* [security](../../../torviello-enforcer/security/README.md) · *Rule:* [13-physical-workspace-remote-work-and-asset-protection.md](../../../torviello-enforcer/security/rules/13-physical-workspace-remote-work-and-asset-protection.md)

**Control objective.** People must protect devices, conversations, records, and physical access wherever work occurs. Controls must match the sensitivity of information and actual threat, remain usable for the workforce, and respect jurisdictional privacy and workplace rules.

#### SEC-13.01 — The organization MUST define requirements for office, home…

**Requirement:** The organization MUST define requirements for office, home, travel, coworking, and other work locations based on information sensitivity, device type, local law, and customer/contract conditions. Restrictions or exceptions MUST be stated, approved, and supported with practical alternatives.

#### SEC-13.02 — Work devices MUST use approved authentication, encryption…

**Requirement:** Work devices MUST use approved authentication, encryption, screen lock, supported security updates, endpoint protection where available, and remote lock/wipe capability proportionate to risk. Removable media MUST be restricted, encrypted, inventoried, and sanitized before reuse or disposal.

#### SEC-13.03 — Workers MUST position screens, control printing, secure…

**Requirement:** Workers MUST position screens, control printing, secure paper records, and avoid discussing confidential work where unauthorized people can see or hear it. Use privacy filters, locked storage, secure disposal, or private rooms where sensitivity warrants.

#### SEC-13.04 — Work locations that host sensitive systems, records…

**Requirement:** Work locations that host sensitive systems, records, or equipment MUST identify authorized access, visitor escort/record requirements, key/card custody, alarm response, and lost credential escalation. Do not leave visitors unattended in restricted areas.

#### SEC-13.05 — When working while traveling, protect devices from theft…

**Requirement:** When working while traveling, protect devices from theft, shoulder surfing, tampering, and unattended access; use approved network protections and avoid sensitive work where privacy cannot be assured. Report loss, suspected tampering, border seizure, or exposure promptly.

#### SEC-13.06 — Loss, theft, damage, unexpected access…

**Requirement:** Loss, theft, damage, unexpected access, fire, flood, power failure, or environmental hazard affecting work assets MUST be reported through a defined route. The owner MUST assess credential revocation, data exposure, business continuity, recovery, and notification needs.

#### SEC-13.07 — Before transfer, return, resale, or disposal…

**Requirement:** Before transfer, return, resale, or disposal, remove organizational accounts and securely erase storage under an approved method; recover licenses and accessories; verify disposal for sensitive media; and record custody transfer where required.

#### SEC-13.08 — People MUST receive concise guidance for the locations…

**Requirement:** People MUST receive concise guidance for the locations and devices they use, including reporting lost assets, safe travel, remote meetings, printing, and household/shared-device boundaries. Training MUST NOT rely on surveillance of personal spaces.
